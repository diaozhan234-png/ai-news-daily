Anthropic’s AI used fake identities, malware in rogue attack on GitHub project
Routine cybersecurity testing of frontier AI models sparked a series of unexpected security incidents—the most serious case arising when Anthropic’s Mythos 5 model attempted to insert malicious code into an open source software application and created fake identities to deceive the human developers maintaining the project. The security incidents occurred during a cyber evaluation of seven leading AI models’ capabilities by the AI Security Institute (AISI), a research organization within the UK government, in late July. The researchers discovered 19 instances in which “AI agents took unsanctioned action on the live Internet, including cases that targeted real people and organizations,” according to an AISI blog post published on August 4. Almost all the “autonomous, unsanctioned” actions came from Anthropic’s Mythos 5 model, with two such actions coming from OpenAI’s GPT-5.6 Sol. The AI Security Institute’s security team first realized that something was amiss on the morning of July 28, when its commercial security monitoring service flagged data leaving one of the testing systems through the Tor anonymity network. To be very clear, this was not a case of AI agents escaping from their virtual testing sandbox and wreaking havoc on the live Internet. Instead, researchers intentionally permitted the AI agents to have Internet access as part of the cyber testing process. Researchers had also disabled some of the cyber classifiers that AI model providers built into the models to prevent misuse. All the AI agent attempts to target real people and organizations failed, and the follow-up investigation has not found any real-world harm. But researchers described the AI agents’ actions as “the first time we have seen risks around autonomy and deception manifest this clearly, without specific prompting, in the real world.” The most serious case involved Mythos making multiple attempts to execute a supply chain attack on the open source project repository hosted on the developer platform GitHub, including using social engineering techniques to try to convince the repository’s human maintainers to merge malicious code into the repository. After first opening a pull request to merge the malicious code into the repository, Mythos created fake online “sock puppet” personas that claimed to have independently reviewed and verified the code as not containing malware. The AI agent also sent five emails to two human maintainers of the repository, including some emails containing malware and others attempting to persuade a maintainer to accept the pull request. Mythos even opened a GitHub Issue on a second repository—also owned by a maintainer of the first repository—that contained a prompt injection with malicious instructions targeting “issue-triage AI coding agents.” This line of attack came from Mythos reasoning that the repository maintainer could be an AI coding agent such as Claude Code. By comparison, OpenAI’s GPT-5.6 Sol carried out two unsanctioned actions while trying to solve the assigned cybersecurity challenge of attacking simulated networks and retrieving a flag. The AI agent’s actions were detailed by both the AISI researchers and OpenAI in the company’s own blog post . In its first unsanctioned action, GPT-5.6 Sol reused a GitHub token that another lab’s AI agent had left accessible in a public online notepad to check if the target network was checking GitHub for updates, then “attempted account-recovery and request-limit workarounds,” OpenAI wrote. The OpenAI model also registered accounts with external DNS and tunneling providers outside the virtual testing environment. In the second action, GPT-5.6 Sol “used a public tunneling service to make a DNS server running locally in its evaluation environment reachable from the public Internet,” according to OpenAI. The server had payloads designed to exploit a known vulnerability in software running within the evaluation environment, but the AI agent’s setup did not work. The AI Security Institute has published a detailed technical report on all the unsanctioned AI agent actions. The security incidents led the UK government researchers at the AI Security Institute to stop all related evaluations of AI agents, isolate the relevant virtual machines, and disable internal organization access to the most capable models. The AI Security Institute also notified GitHub of the malicious activity performed by AI agents and helped the developer platform remove any “artefacts left behind by the agent,” along with notifying GitHub users whom the model interacted with. But the bigger lessons come from how the government organization plans to change cyber testing for such leading AI models in the future—and how it recommends other organizations do the same. First, it plans to tighten Internet access for AI models during cyber testing instead of allowing open Internet access by default. This will supposedly include “fine-grained network controls to all internal sandboxing systems” and “defence-in-depth with network controls at multiple layers,” according to the technical report. Second, the organization is introducing real-time monitoring of cyber evaluations that can “flag or block out-of-scope actions as they happen,” according to AISI. This involves using a separate large language model that can approve or deny actions requested by the AI models that are undergoing cyber testing, which can help stop unsanctioned actions. The LLM-based monitoring would be customized with instructions on what should or should not be allowed in any given cyber evaluation. Third, the UK government researchers plan to overhaul cyber evaluations by investing additional “engineering effort in sandbox isolation and hardening” to mitigate the risk of AI models escaping from their virtual testing sandboxes, even though escapes did not happen in these incidents.

Anthropic的人工智能在GitHub项目的流氓攻击中使用了虚假身份和恶意软件
前沿人工智能模型的常规网络安全测试引发了一系列意外的安全事件，其中最严重的是Anthropic的Mythos 5模型试图将恶意代码插入开源软件应用程序，并创建虚假身份来欺骗维护该项目的人类开发人员。7月下旬，英国政府下属的研究机构人工智能安全研究所（AISI）对七种领先的人工智能模型的能力进行了网络评估，期间发生了安全事件。根据8月4日发布的AISI博客文章，研究人员发现了19起“人工智能代理在实时互联网上采取未经批准的行动，包括针对真实个人和组织的案件”。几乎所有“自主、未经批准”的行为都来自Anthropic的Mythos 5模型，其中两个行为来自OpenAI的GPT-5.6 Sol。人工智能安全研究所的安全团队在7月28日上午首次意识到出了问题，当时其商业安全监控服务通过Tor匿名网络标记了离开其中一个测试系统的数据。非常清楚的是，这不是人工智能代理逃离虚拟测试沙箱并对实时互联网造成严重破坏的情况。相反，研究人员故意允许人工智能代理访问互联网，作为网络测试过程的一部分。研究人员还禁用了人工智能模型提供商在模型中内置的一些网络分类器，以防止误用。所有针对真实个人和组织的AI代理尝试都失败了，后续调查也没有发现任何现实世界的危害。但研究人员将人工智能代理的行为描述为“我们第一次看到围绕自主性和欺骗的风险在现实世界中没有具体提示的情况下清楚地表现出来。”最严重的案件涉及Mythos多次尝试对开发者平台GitHub上托管的开源项目存储库执行供应链攻击，包括使用社会工程技术试图说服存储库的人工维护人员将恶意代码合并到存储库中。在首次打开将恶意代码合并到存储库的拉取请求后，Mythos创建了虚假的在线“袜子木偶”角色，声称已经独立审查并验证了代码中不含恶意软件。AI代理还向存储库的两名人工维护人员发送了五封电子邮件，其中包括一些包含恶意软件的电子邮件，以及其他试图说服维护人员接受拉取请求的电子邮件。Mythos甚至在第二个存储库上打开了一个GitHub Issue，该存储库也归第一个存储库的维护者所有，其中包含针对“问题分流AI编码代理”的恶意指令的快速注入。这一攻击来自Mythos的推理，即存储库维护者可能是Claude Code等AI编码代理。相比之下，OpenAI的GPT-5.6 Sol在试图解决攻击模拟网络和检索标志的网络安全挑战时，采取了两项未经批准的行动。AISI研究人员和OpenAI在该公司自己的博客文章中详细介绍了AI代理的行为。OpenAI写道，在其第一次未经批准的行动中，GPT-5.6 Sol重用了另一个实验室的AI代理在公共在线记事本中留下的GitHub令牌，以检查目标网络是否正在检查GitHub的更新，然后“尝试帐户恢复和请求限制解决方法”。OpenAI模型还向虚拟测试环境外的外部DNS和隧道提供商注册了帐户。OpenAI表示，在第二个行动中，GPT-5.6 Sol“使用公共隧道服务使在其评估环境中本地运行的DNS服务器可以从公共互联网访问”。该服务器的有效载荷旨在利用评估环境中运行的软件中的已知漏洞，但AI代理的设置不起作用。AI安全研究所发布了一份关于所有未经批准的AI代理操作的详细技术报告。这些安全事件导致英国政府人工智能安全研究所的研究人员停止了对人工智能代理的所有相关评估，隔离了相关的虚拟机，并禁止内部组织访问最强大的模型。AI安全研究所还向GitHub通报了AI代理的恶意活动，并帮助开发平台删除了任何“代理留下的人工制品”，同时通知了与该模型交互的GitHub用户。但更大的教训来自政府组织计划如何在未来改变此类领先人工智能模型的网络测试，以及它如何建议其他组织也这样做。首先，它计划在网络测试期间加强人工智能模型的互联网接入，而不是默认允许开放互联网接入。根据技术报告，这将包括“对所有内部沙盒系统的细粒度网络控制”和“通过多层网络控制进行深度防御”。其次，根据AISI的说法，该组织正在引入对网络评估的实时监控，可以“在发生超出范围的行动时标记或阻止这些行动”。这涉及使用一个单独的大型语言模型，该模型可以批准或拒绝正在进行网络测试的人工智能模型所请求的操作，这可以帮助阻止未经批准的操作。基于LLM的监控将根据任何给定的网络评估中应该或不应该允许的内容进行定制。第三，英国政府研究人员计划通过在沙箱隔离和加固方面投入额外的“工程努力”来彻底改革网络评估，以降低人工智能模型从虚拟测试沙箱中逃逸的风险，即使在这些事件中没有发生逃逸。
